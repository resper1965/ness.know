# OAuth no /mcp com escopo por pessoa: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cada pessoa autoriza o ness.work (ou outro cliente MCP) com o próprio login e recebe uma chave `nesskb_` pessoal, cujo escopo vem de regras por pessoa e "padrão para todos", avaliadas a cada chamada. As chaves por agente de hoje continuam iguais.

**Architecture:** Copia a estrutura de `resper1965/ness-brain` (`cloudflare/src/mcp-oauth.ts`, migração 0047, teste), já em produção com o ness.work: descoberta (RFC 9728 e 8414), registro dinâmico de cliente público, `authorize` atrás do Access, `token` com PKCE S256. O token é uma linha em `chaves` com `pessoa` preenchida; em `clienteDe` (src/mcp.ts), chave com `pessoa` tem o escopo calculado de `acesso_regras` em vez do JSON gravado. Nada mais no /mcp muda: `visivel`, busca e skills já leem `Cliente`.

**Tech Stack:** Cloudflare Workers, D1, Rate Limiting binding, TypeScript, vitest com `node:sqlite` (`test/sqlite.ts`).

**Spec:** o texto de requisitos do pedido de 11/11/2026 (este plano o corrige nos pontos da seção "Diferenças para o texto").

## Diferenças para o texto (conferidas no código)

1. **Testes são vitest, não `node:test`.** O repositório usa vitest com `bancoTeste()`.
2. **Cota de registro:** o brain usa `consumir()` em D1; aqui existe o binding Rate Limiting (`LIMITE_AUTH`). Cria-se `LIMITE_REGISTRO_IP` (10 por 60 s, chave = IP) e `LIMITE_REGISTRO` (60 por 60 s, chave fixa). A do IP vem antes; a global só conta registro válido.
3. **Formato de data:** `chaves.expira_em` é `AAAA-MM-DD HH:MM:SS` e é comparado com `datetime('now')`. O ISO do brain (`...T...Z`) compara errado no mesmo dia. Usar `datetime('now', '+30 days')` no SQL.
4. **Id da chave OAuth precisa ser UUID** (a rota de revogar casa `/api/chaves/[0-9a-f-]{36}`). O id determinístico vira `8-4-4-4-12` hex do SHA-256 de `client_id|pessoa`, não `mcp-oa-…`.
5. **Rotas fora do Worker:** `assets.run_worker_first` só lista `/api/*`, `/mcp`, `/health`. Acrescentar `/oauth/*` e `/.well-known/*`, senão os arquivos estáticos respondem no lugar do Worker.
6. **`authorize` usa `emailDoAcesso()`, não `adminDe()`**: qualquer colaborador liberado no Access pode autorizar, não só `ADMIN_EMAILS`. O Access precisa de uma aplicação própria para `/oauth/authorize` com política mais ampla que a do painel.
7. **Auditoria não existe:** não há `eventos_governanca`. Cria-se a tabela `auditoria` (concessão, revogação, mudança de regra), com ator e detalhe, sem conteúdo.
8. **Grupo:** o `emailDoAcesso` só lê o e-mail; o /mcp não tem o JWT do Access nas chamadas, então grupo do Entra não dá para avaliar a cada chamada. Decisão: **grupo = lista de e-mails mantida no painel** (tabela `acesso_grupos`). Entra por último (Task 5) e pode ficar fora do primeiro PR.
9. **Escopo calculado, definição exata:** pacotes = união das regras que valem para a pessoa (padrão + grupos + pessoa). Para cada pacote, se alguma regra o libera inteiro, vale inteiro; senão, vale a união dos títulos listados.
10. O texto cita "Cloudflare Access managed OAuth"? Não: segue o fluxo próprio do brain. O spike planejado antes (app `mcp-oauth` com Managed OAuth) deixa de ser necessário.

## Global Constraints

- Português do Brasil, direto; marcas da ness. em caixa baixa.
- Sem segredo no código; token só em hash; código de autorização só em hash, uso único, 60 s.
- Chaves por agente: comportamento e testes atuais inalterados.
- `npm test && npm run check` verdes; sem merge e sem deploy por conta própria; branch `ccr-4d9339a0-31h965` sem force push; PR como rascunho.
- Cliente só público (`token_endpoint_auth_method: none`); PKCE S256 obrigatório; sem refresh token.
- `ponytail: sem refresh token, chave de 30 dias | limite: o cliente reconecta a cada 30 dias, com a pessoa presente | gatilho: reclamação de reconexão ou agente rodando sem pessoa (emitir refresh token) | dono: diretoria@ness.com.br`
